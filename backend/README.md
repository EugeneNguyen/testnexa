# TestNexa backend

Codebase skeleton: FastAPI + PostgreSQL + SQLAlchemy 2.0 + Alembic
(ADR-0002). This is schema + app scaffold only — no business/feature routes
beyond `/health`, no auth/RBAC logic implemented yet (see `app/core/security.py`
and `app/core/rbac.py`, which are stubs). Feature implementation is a later task.

## Dev setup

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# Copy/edit env vars (DATABASE_URL, JWT_SECRET, ...) — see app/core/config.py
# for the full Settings list. A .env file in this directory is picked up
# automatically.

uvicorn app.main:app --reload
```

Health check: `GET http://localhost:8000/health` → `{"status": "ok"}`.

## Tests

```bash
pytest -v
```

### Integration tests

`tests/integration/` is a separate suite from `tests/unit/`: instead of the
in-process `TestClient`, it makes real HTTP requests (via `httpx.AsyncClient`)
against a server that must already be running. It skips itself cleanly (not
an error) if that server isn't reachable, so a plain `pytest` run of the
whole `tests/` tree is unaffected.

To actually run it, bring the stack up first, then point it at the exposed
nginx port (which proxies `/api/health` to the backend's `/health`):

```bash
docker compose --profile dev up --build

# in another shell:
TEST_API_BASE_URL=http://localhost:54593/api pytest backend/tests/integration
```

You can also point it directly at a locally-running backend (bypassing
nginx) by omitting `TEST_API_BASE_URL` (defaults to `http://localhost:8000`)
or setting it explicitly.

## Database migrations

Models live under `app/models/` (11 files, one per Database Document
cluster — see `app/models/__init__.py` for the full registry and a
documented count deviation).

`alembic/versions/` is intentionally empty in this scaffold. The initial
migration is autogenerated against a live Postgres, not hand-written, to
guarantee it matches the models exactly:

```bash
alembic revision --autogenerate -m "initial schema"
alembic upgrade head
```

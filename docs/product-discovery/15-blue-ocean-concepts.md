# 15 — Blue Ocean Concepts

**Note on numbering:** requested as "13 — Blue Ocean Concepts," renumbered to 15 (06–14 already in use). See [00-overview.md](00-overview.md) for the full index.

20 concepts, each required to shift the value curve (09) rather than incrementally improve a factor competitors already own. Every concept is traced back to a specific finding in 06–14 — none of these are invented from a blank page, they're the logical extensions of the whitespace triangulated four separate ways (09/06/12/13). All are **HYPOTHESES/RECOMMENDATIONS**, unvalidated against real buyers.

| # | Concept | What it does | Value-curve shift | Grounded in |
|---|---|---|---|---|
| 1 | **MCP-native from day one** | First-party MCP server as core architecture, not a bolt-on add-on module | Create — no competitor studied ships this self-hosted | 06, 09 |
| 2 | **BYO-LLM test generation** | AI test-case/script generation runs against a local model or the customer's own API key/endpoint — never a vendor-operated cloud model | Create — breaks the self-hosted-vs-AI trade-off every competitor is stuck in | 06, 09, 10 |
| 3 | **Human/AI accountability ledger** | Every artifact (test case, execution, defect) carries a visible, exportable record of which `Actor` (human or agent) created/modified it | Create — turns a schema decision (07) into a marketed trust feature | 07, 10 |
| 4 | **First-class Auditor role** | Read-only role plus one-click RTM/evidence export, explicitly built and marketed for the external-auditor persona, not repurposed from an internal role | Raise — no competitor markets a role for this stakeholder | 03, 14 |
| 5 | **Continuous/event-driven traceability** | RTM stays always-current as executions happen, instead of being assembled on demand at audit time | Create — imported directly from the GRC industry's core mechanic | 12 |
| 6 | **One-click dual-standard document export** | Same underlying data renders as an IEEE 829/ISO 29119-3-formatted Test Plan *and* an ISTQB CTFL-vocabulary technique-coverage report | Create — nobody studied claims both standards correctly, let alone auto-generates both | 07, 08 |
| 7 | **Opt-in rigor / progressive adoption** | Teams start with a flexible, Notion-style lightweight tracker; `TestCondition`/CTFL structure is switched on later without a data migration | Reduce (adoption friction) + Raise (available depth) simultaneously | 07 (open Q1), 12, 13 |
| 8 | **Usage-based self-hosted pricing** | Free unlimited seats; pay for execution volume, support tier, or managed hosting — not per-user count | Eliminate — removes the #1 cited industry pain directly (03) | 03, 17 (Sentry model) |
| 9 | **Support-subscription revenue, not feature-paywall** | Core traceability/compliance features stay free and open; revenue comes from support/SLA/managed hosting (Red Hat model), not gating the features regulated buyers need most | Eliminate the Squash-TM-style trust risk of paywalling the exact features the target segment needs | 04, 05, 17 |
| 10 | **Policy-as-code testing governance** | Encode organizational testing rules ("every P0 requirement needs ≥2 test cases using a documented technique") as enforceable, versioned policy — Sentinel-style | Create — no test management tool studied offers programmable governance | 17 (HashiCorp model) |
| 11 | **Community connector marketplace** | Automation-framework and QMS/GRC export connectors built and shared by users/community, not solely vendor-maintained | Create — imports a distribution mechanic no competitor in this category uses | 14, 17 (Zapier/GitHub Marketplace) |
| 12 | **Free ISTQB technique-practice sandbox** | A separate, permanently free tier aimed at exam candidates/training providers to practice test-design techniques hands-on | Create — opens a market segment (02 job #10, 11 Tier 3) nobody studied targets at all | 02, 11, 17 (Duolingo model) |
| 13 | **Auditor/consultant partner program** | Compliance consultants and contract auditors run the product across multiple client orgs (using the multi-tenant `OrgMembership` design), with a referral/rev-share arrangement | Create — a distribution channel no self-hosted OSS competitor has built | 07, 11, 17 (Vanta model) |
| 14 | **Evidence-bundle API for downstream GRC/QMS platforms** | Purpose-built export/API matching what Vanta/Drata/Greenlight Guru expect as input, positioning this product as their upstream evidence source | Create — the B2B2B distribution angle surfaced in 14 | 12, 14 |
| 15 | **Production-incident-to-coverage linkage** | Pull incidents from Datadog/Sentry-class tools and automatically flag "no test case covered this," turning gaps into a visible, quantified argument for testing investment | Create — closes a loop no competitor studied addresses (14's flagged v2 gap) | 14 |
| 16 | **Community template/technique library** | Shareable test-suite templates and worked design-technique examples, contributed by users (Figma-community-style) | Create — acquisition flywheel independent of the sales motion | 17 |
| 17 | **Optional e-signature-grade approvals** | `Approval` records can be upgraded to non-repudiable, timestamped/hash-chained sign-off for regulated buyers specifically, left as a plain record for everyone else | Raise, opt-in only | 07, 12 (DocuSign model) |
| 18 | **"10-minute Docker Compose to first traceable test" commitment** | An explicit, measured product commitment attacking Squash TM's and full ALM suites' worst-scored factor (ease of adoption) head-on | Raise — directly targets Group B/F's weakest point (13) | 09, 13 |
| 19 | **Agent-governance framing for security/platform buyers** | Market the Actor-scoped RBAC model to security/platform teams evaluating "AI agent governance," not just QA managers — a different budget line entirely | Create — new buyer persona, not a new feature | 07, 08, 11 |
| 20 | **"Coexist with Jira," native two-way sync** | Explicitly do not ask Jira-centric teams to migrate off Jira; sync `Requirement` bidirectionally, matching the Greenlight Guru coexistence pattern | Raise — removes Strategic Group D's biggest switching barrier (13) | 12, 13 |

## Insight

**INSIGHT:** Concepts cluster into four coherent bets, not twenty scattered features — (a) #1–3, #6, #17, #19: the human/AI/standards-native data model as a trust and governance story; (b) #4–5, #14–15: continuous, exportable evidence as the actual product (not test-case CRUD); (c) #8–9: a pricing/business-model change that's arguably as differentiating as any feature; (d) #7, #11–13, #16, #18, #20: distribution and adoption mechanics borrowed wholesale from adjacent industries. **RECOMMENDATION:** an MVP should draw from all four clusters in small amounts rather than fully building one — a differentiated data model with no viable pricing model, or a great pricing model with no distribution mechanic, both fail for reasons unrelated to the core insight. This sequencing question belongs in the not-yet-produced MVP-scoping doc.

# ADR-0049: FRONTEND-1 co-locate Vitest unit tests next to source — supersedes the `frontend/tests/` mirror convention

**Date:** 2026-09-09
**Status:** Accepted
**Deciders:** xuanbinh91@gmail.com (CTO)
**Related:** [ADR-0043](0043-atomic-design-tiering-for-frontend-components.md) (atomic-design directory tiering — this ADR's co-location pattern is the inverse of `frontend/CLAUDE.md`'s pre-existing "tests mirror `src/`" rule that ADR-0043 itself only partially closed, by relocating some loose root tests under the new tiered subfolders while leaving the mirror-`src/` convention itself in force), `frontend/CLAUDE.md` "Unit tests live in `frontend/tests/`" paragraph (this ADR supersedes that rule), [ADR-0042](0042-adminlte-design-system.md) (AdminLTE v4 design system — unaffected, no CSS/JS surface change here)

## Context

Every Vitest + RTL spec in this repo currently lives under `frontend/tests/`, mirroring `frontend/src/`'s directory shape (e.g. `src/components/atoms/button/button.tsx` → `tests/components/atoms/Button.test.tsx`). The convention was deliberate — `frontend/CLAUDE.md` documents it explicitly — and the rationale was real: an outside reader running `find src -iname "*.test.*"` should not falsely conclude "zero coverage" before checking `frontend/tests/`. That rationale survives, but the convention itself has accumulated enough friction over the repo's life to be worth flipping:

1. **Discoverability cost:** when a component lives at `frontend/src/components/molecules/fk-autocomplete/fk-autocomplete.tsx`, its test sits at `frontend/tests/components/molecules/FkAutocomplete.test.tsx` — four levels deep into a parallel tree a reader has to know exists. New contributors reliably miss it, and the repo's own CLAUDE.md already documents at least one wasted verification round-trip caused by exactly this (REQ-4, 2026-09-06: a fresh `find src` check concluded no coverage existed before someone checked `frontend/tests/`).
2. **Test/source drift is invisible from the file tree.** A moved/renamed source file whose test was at a mirrored path gives no signal at either end — the source's new path is silent, the test's old path still appears green at `npm run test`, and the gap only surfaces if someone notices the test's `import "../../../src/..."` now resolves nothing.
3. **Per-story multi-file test naming** (`ProjectDetail.tsx` + `ProjectDetail.test.tsx` + `ProjectDetail.TestConditions.test.tsx` + …) already encodes the convention's own opposite assumption — that several spec files for one source *belong together*, in one folder, by name. Keeping them physically separate from the source fights the convention's own naming choice.
4. **No tooling dependency on the layout.** Vitest's default `**/*.{test,spec}.?(c|m)[jt]s?(x)` glob discovers `*.test.tsx` files wherever they live, including under `src/`. The only config that references the current layout is `vite.config.ts`'s `setupFiles: ["./tests/setup.ts"]` — one path string to update, not a structural rewrite.

This ADR's literal ask: move all Vitest unit tests to live next to their source under `frontend/src/`. E2E (Playwright) tests under `e2e/tests/` are explicitly out of scope — different runner, different folder, different problem, same as before.

## Decision

1. **All Vitest unit tests move from `frontend/tests/**.test.{ts,tsx}` to `frontend/src/**.test.{ts,tsx}`**, co-located next to the source file they cover. Every test moves; the layout becomes uniformly co-located, not hybrid (one place to look, no "is this the component's test or the page's test" judgment call).
2. **Per-source-file placement, mirroring the existing `src/` shape, not flattening.** A test for `frontend/src/components/molecules/fk-autocomplete/fk-autocomplete.tsx` moves to `frontend/src/components/molecules/fk-autocomplete/fk-autocomplete.test.tsx`, not to `frontend/src/components/molecules/fk-autocomplete.test.tsx` — the source's own folder convention (each component in its own subfolder with an `index.ts` barrel, ADR-0043) is preserved verbatim. Per-story multi-file test naming (`ProjectDetail.test.tsx` + `ProjectDetail.TestConditions.test.tsx` + …) lands in the same folder as `ProjectDetail.tsx`, exactly the grouping the naming already implies.
3. **Relative imports in every moved file shorten to `./<sibling>` or `./` via the existing barrel.** Every moved test currently does `from "../../../src/components/atoms/button"` — after the move, that becomes `from "./button"` (or `from "./"` against the same folder's `index.ts`). Mechanical, mechanical across 69 files.
4. **`frontend/tests/` becomes `frontend/test-setup/`, containing only `setup.ts`.** The single non-test file currently in the folder (`setup.ts`, jsdom polyfills for `localStorage` + `matchMedia`, not a test of any component) gets a new parent folder whose name describes the contents — test *infrastructure*, not test *files*. `vite.config.ts`'s `setupFiles` becomes `["./test-setup/setup.ts"]`. This is the only folder name change in the move; the folder's old name was misleading the moment its contents stopped being tests.
5. **`tsconfig.json`'s `include`/`exclude` is unchanged.** Verified before merging — no `tests/` exclusion exists in the current config that would silently break Vitest after the move; the change is purely physical.
6. **Historical plan docs (`docs/superpowers/plans/*.md`) that reference `frontend/tests/...` paths are *not* retroactively rewritten.** Those are records of what each story shipped *at the time*, in paths that were correct when written. Future grep will surface both spellings — that's honest, not a bug. A one-line note in this ADR's Consequences below points future readers at the post-merge convention without rewriting history.
7. **E2E (Playwright) test files referencing `frontend/tests/...` in their own comments get a one-line comment edit, not a path rewrite.** Comments in `e2e/tests/shell6-org-switcher.spec.ts` and `e2e/tests/shell7-sidebar-mini.spec.ts` name a specific Vitest file by its old path; the file is still the same file, just at a new path. Edit the comment to match, don't reach for a wholesale rewrite.
8. **`frontend/CLAUDE.md`'s "Unit tests live in `frontend/tests/`" paragraph is rewritten** to state the new convention in its place — keeping the paragraph in the doc but with the rule inverted, so any future contributor (human or sub-agent) who skims the doc finds the current rule first, not the old one.

Vitest config: one-line edit (`setupFiles` path). `package.json` test scripts: unchanged.

## Consequences

**Positive:** `find frontend/src -iname "*.test.*"` becomes the universal "where are the tests" answer — no parallel tree, no "check `frontend/tests/` first" caveat. Source/test drift becomes visible at the file tree: a moved source whose old test still references `from "../../../src/<old-path>"` shows up immediately as a sibling with a stale import, not as a green-at-`tests/` ghost whose old source path now resolves to nothing. Multi-file test conventions like the per-story `ProjectDetail.*` set land where the naming already implies they belong, removing the friction the convention was quietly creating against its own intent.

**Negative / accepted trade-offs:**

- **`find src -iname "*.test.*"` no longer returns empty.** This is the inverse of the original convention's rationale. The risk it carried — "looks like zero coverage" — is replaced by a smaller, opposite risk — "looks like full coverage at first glance even when only some folders have tests" — which the per-folder test inventory in this repo's own existing test runs (and the explicit `data-testid`-based Playwright specs) catch just as well as before. `frontend/CLAUDE.md`'s rewritten paragraph names the new convention directly, so the "where to look" question has one answer, not two.
- **Historical plan docs (`docs/superpowers/plans/*.md`) carry now-stale `frontend/tests/...` paths.** ~10 hits across `auth-2-session-persistence`, `auth-3-logout`, `ds-1-form-field`, and similar. **Deliberately not rewritten** — those paths were correct at the time each plan was committed, and rewriting them would erase that historical record. Future readers seeing `frontend/tests/...` in a 2026-09-03-era plan should treat it as the path-as-of-that-commit, not the current one; the current convention is this ADR.
- **`frontend/tests/` → `frontend/test-setup/` is a one-time rename.** Any external tool that hardcoded the literal `frontend/tests` string (none exists in this repo's own scripts, verified) would break. None found; `package.json`'s `test` script invokes Vitest by name, not by path, and no `npm`/`grep`/`find` script outside `CLAUDE.md` references the folder by literal name.
- **Vitest's default glob includes every `*.test.{ts,tsx}` under `src/`.** A test file importing a real `.tsx` source from the same tree is exactly the behavior we want — already the behavior today. No change in coverage semantics; only in physical file location.

No backend, database, or API change anywhere in this ADR — the entire surface is frontend file layout.

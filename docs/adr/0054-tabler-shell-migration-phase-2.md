# ADR-0054: Tabler shell migration, Phase 2 — AppSidebar/AppHeader/AppShell/AppFooter move to Tabler markup, cascade flips to Tabler-wins

**Date:** 2026-09-10
**Status:** Accepted
**Deciders:** xuanbinh91@gmail.com (CTO)
**Related:** [ADR-0053](0053-tabler-install-phase-1-cdn.md) (Tabler v1.5.1 CDN install, Phase 1 — this ADR is the "separate, explicit instruction" that ADR-0053's Consequences named as the gate for Phase 2), [ADR-0042](0042-adminlte-design-system.md) (AdminLTE v4 — **partially superseded by this ADR**, see Decision), [Tabler page-layout docs](https://docs.tabler.io/ui/layout/page-layouts)

## Context

CTO directive: replace the app's sidebar and header with Tabler's own documented page-layout markup (sidebar-layout pattern: `.page` → `.navbar-vertical` aside + `.page-wrapper` → `header.navbar` + `main.page-body` → `footer.footer`). Confirmed scope during planning (two `AskUserQuestion` rounds):

1. **This is intentionally a full design-system-direction commit (AdminLTE → Tabler), executed incrementally.** The shell (sidebar, header, the `AppShell` composition root, footer) moves now; every other screen (`OrgHome`, `ProjectDetail`, the generic admin CRUD surface, forms, modals, ...) stays on AdminLTE markup until a future, separately-scoped pass migrates it. This mirrors ADR-0042's own big-bang precedent in *direction* but not in *size* — ADR-0042 moved every screen in one branch; this ADR deliberately does not, because the CTO's own instruction was scoped to "sidemenu and header," not the whole app.
2. **Cascade order flips: Tabler wins globally, effective this ADR.** ADR-0053 loaded Tabler's CSS ordered so AdminLTE continued to win every conflicting selector (zero visible change, Phase 1's whole point). Making the sidebar/header actually render with Tabler's own tokens requires the opposite ordering — confirmed explicitly with the CTO, who accepted the named consequence: **every unmigrated page's `.card`/`.btn`/`.table`/grid (AdminLTE classes, same literal names Tabler's own Bootstrap-5 base also defines) shifts to Tabler's slightly different look too, not just the shell.** This is the same cascade-conflict risk ADR-0042 itself named for CoreUI+AdminLTE and ADR-0053 named for Tabler+AdminLTE — accepted here as an explicit, temporary, mid-migration state rather than avoided by scoping the CSS somehow (Tabler ships no scoped/namespaced build; a shadow-DOM or iframe boundary was not considered proportionate for two components).

## Decision

- **`AppSidebar`, `AppHeader`, `AppShell`, `AppFooter` are rewritten to Tabler's own markup and class names**, read verbatim from the CTO-supplied Tabler page-layout doc (the "Sidebar layout" sample, not the "Folded sidebar" variant — see Scope reduction below):
  - `AppShell`: AdminLTE's `.app-wrapper` CSS grid → Tabler's `.page` flow layout. `<aside class="navbar navbar-vertical navbar-expand-lg">` (rendered by `AppSidebar`) is a direct child of `.page`; `.page-wrapper` follows, containing `AppHeader`'s `<header class="navbar navbar-expand-md d-print-none">`, then `<main class="page-body">` (breadcrumb + `{children}`), then `AppFooter`'s `<footer class="footer footer-transparent d-print-none">`. No CSS-grid named areas, no `.sidebar-overlay` scrim (Tabler's vertical navbar collapses its own `<div class="collapse navbar-collapse">` in normal document flow on mobile, not an off-canvas layer needing a click-outside backdrop).
  - `AppSidebar`: `.app-sidebar` → `.navbar.navbar-vertical.navbar-expand-lg`; `.sidebar-brand`/`.brand-link` → `.navbar-brand`; `.sidebar-menu`/`nav-treeview` groups → `.navbar-nav` with `.nav-item.dropdown`/`.dropdown-toggle`/`.dropdown-menu` for the org/project entity groups (Bootstrap's dropdown component, matching how Tabler's own folded-sidebar example renders a group — used here in the *unfolded* rail too, since Tabler's CSS renders an unfolded vertical navbar's `.dropdown-menu.show` inline rather than as a floating flyout; confirmed live against the isolated stack, not assumed from source, per this repo's own "verify empirically" testing rule). Group open/closed state, the org/project-mode `navGroups`/`navItems`/`bottomNavItems` generation logic, and every `data-testid` are unchanged — only the wrapping markup and CSS classes around them changed.
  - `AppHeader`: `.app-header` → `header.navbar.navbar-expand-md.d-print-none`; org-switcher/color-mode dropdowns keep their existing hand-rolled `useDropdown` state machine (no `data-bs-toggle` wired to Tabler's own loaded JS — same "React owns this state, the class string is all that's read" discipline ADR-0042 established, now applied to Tabler's JS bundle too, avoiding the duplicate-listener risk ADR-0053's Consequences flagged). The sidebar toggler **stays in the header** (not moved into the aside, the placement Tabler's own doc snippet shows) — deviation kept deliberately: `AppShell` already owns sidebar open/closed state and hands `AppHeader` an `onToggleSidebar` callback; moving the button would only relocate markup, not simplify the state ownership, and keeps every existing `sidebar-toggler`-in-header test assertion structurally valid.
  - `AppFooter`: `.app-footer` → `footer.footer.footer-transparent.d-print-none`, `list-inline list-inline-dots` for the two link groups (previously two bare `<div>`s) — same two pieces of static text, no new content.
  - Color mode (`useColorMode`, `data-bs-theme` attribute) is functionally unchanged — Tabler is also Bootstrap-5-based and reads the same attribute. **The `localStorage` key renames from `lte-theme` to `tabler-theme`**, matching Tabler's own documented convention (`tabler-theme.js`) instead of AdminLTE's — a deliberate one-time reset of any stored preference, same accepted trade-off ADR-0042 §4.3 made the first time this key was renamed (CoreUI → AdminLTE).
- **`frontend/index.html`'s Tabler `<link>` moves from the `<head>` to immediately after the `<script type="module" src="/src/main.tsx">` tag in `<body>`** — the exact move ADR-0053's own Alternatives section named and deferred ("revisit this ordering choice deliberately once the real migration begins moving screens onto Tabler markup"). This is what flips the cascade: Vite injects `main.tsx`'s CSS imports (AdminLTE, which bundles all of Bootstrap 5 itself — see `main.tsx`'s own comment — plus Font Awesome) at the module script's position, so a Tabler `<link>` placed after it in document order now wins every conflicting selector, project-wide.
- **Scope reduction: the "Folded sidebar" (`navbar-folded`/`navbar-folded-hover`, pin button, `localStorage` `tabler-sidebar` key) and "Section labels" (`nav-section-title`) features from the same Tabler doc are deliberately NOT implemented this pass.** AdminLTE's `sidebar-mini` icon-only collapsed rail (SHELL-7, ADR-0046) is retired without a Tabler replacement — the sidebar is either fully shown (desktop) or fully hidden behind the mobile toggler; there is no third, icon-only rail state. This is a real, visible feature reduction, named explicitly rather than silently dropped: `sidebar-mini`/fold-to-rail is a candidate for a future story if wanted, using Tabler's own `navbar-folded-hover` + pin-button pattern (both already documented in the CTO's own pasted doc, just not built yet).
- **No backend/database/API surface change.**

## Consequences

- **ADR-0042 (AdminLTE) is marked `Partially superseded by 0054`** — AdminLTE remains the live design system for every screen this ADR does not touch (all bespoke pages, the generic admin CRUD surface, forms, modals). Only the 4 shell components move. A future ADR will mark ADR-0042 fully superseded once the remaining screens migrate, the same two-step pattern ADR-0042 itself used against ADR-0012.
- **Every unmigrated page's rendered appearance shifts**, per the Context section's named trade-off — `.card`/`.btn`/`.table`/grid utilities now resolve against Tabler's tokens, not AdminLTE's. No layout-breaking change is expected (both are Bootstrap-5-based, same class contracts), but colors/spacing/shadows will look visibly different until each page migrates. Flagged for the isolated-stack manual-verification pass this change gets before merge (root `CLAUDE.md`'s own "100% TC coverage doesn't substitute for a human look" rule applies directly here).
- **`sidebar-mini`'s 3 associated test files need real rework, not just a class-name find/replace:**
  - `AppShell.test.tsx`'s SHELL-7 sidebar-mini assertions (`sidebar-mini`/`sidebar-collapse`/`sidebar-open` body classes) are retired — Tabler's shell keeps no body-level state classes at all; the sidebar's own open/closed state lives on a `<div class="collapse navbar-collapse">` local to `AppSidebar`.
  - `e2e/tests/shell7-sidebar-mini.spec.ts` (the icon-rail hover/click behavior) is retired outright — the feature it tests no longer exists, per the scope reduction above. Not rewritten as a Tabler equivalent, since the fold feature itself isn't being built this pass.
  - `e2e/tests/ds4-tabler-cdn-no-regression.spec.ts` (ADR-0053's own regression guard, asserting AdminLTE stays visually dominant and Tabler renders inert) is **superseded by this ADR's own explicit intent** — its central assertion ("loading Tabler causes zero visible change") is now false by design. Rewritten to assert the *new* invariant instead: the shell renders with Tabler's own classes, and the specific `.card`/`.btn` tokens on an unmigrated page now resolve to Tabler's values, not AdminLTE's — the mirror-image check of what it used to assert.
- **`AppSidebar.test.tsx`'s brand-logo-swap assertions (`sidebar-brand-logo-xl`/`sidebar-brand-logo-xs`, BRAND-1/ADR-0048) are retired.** Tabler's vertical navbar has no equivalent mini-rail logo cross-fade (that mechanism was AdminLTE's `sidebar-mini` CSS, gone per the scope reduction above) — a single `sidebar-brand-logo` testid replaces the pair. `ADR-0048`'s own Decision §6/§3.3 (both logo slots render unconditionally) no longer applies to this component; not silently dropped — recorded here as the forward-pointer BRAND-1's own logo-slot decision needed once its target markup stopped existing.
- **`lte-theme` → `tabler-theme` localStorage key rename** is a one-time, accepted reset of any user's stored color-mode preference (same trade-off ADR-0042 §4.3 already accepted once).
- Tabler's own JS bundle (`tabler.min.js`, loaded since ADR-0053 Phase 1) is still not driving any of this app's interactive state — every dropdown/collapse/treeview-equivalent remains a hand-rolled React `useState` toggling literal Tabler class strings, continuing the "we don't vendor the design system's own JS plugins" rule ADR-0042 established, now applied to Tabler.
- **Known open item, not resolved this pass:** the folded/pinned icon-rail sidebar (Tabler's `navbar-folded-hover` + pin button) is a plausible future story to recover the UX SHELL-7's `sidebar-mini` used to provide, once the rest of the app has also migrated onto Tabler.

### Amendment (2026-09-11): header items restyled onto Tabler's `.nav-item`/`.nav-link` pattern, and a real Popper-gating bug found + fixed

Direct CTO instruction after the isolated-stack handoff ("also change the items in header like the tabler"): the 3 header controls (org switcher, color mode, log out) moved off the `Button` atom's bordered `.btn-outline-*` pill onto Tabler's own header sample markup — `div.nav-item` wrapping a plain, borderless `.nav-link`, matching the CTO-supplied doc's `<div class="nav-item"><a class="nav-link ...">` shape (as a real `<button>`, not `<a href="#">`, since these are actions/toggles, not navigation). Every `data-testid`/`aria-label` and the underlying state machines are unchanged.

**Found live while re-verifying, not from source:** clicking a header dropdown's toggle a second time (to close it, without selecting an item or clicking outside) failed — Playwright's own "element intercepts pointer events" error, not a broken click handler. Root cause, traced via Chrome DevTools Protocol against a live instance: Tabler v1.5.1's own CSS gates `.dropdown-menu`'s `top:100%` positioning behind a `[data-bs-popper]`/`[data-tblr-popper]` attribute-presence selector — set only when Bootstrap's real Popper-driven dropdown JS initializes the element. This app deliberately never runs that JS (every dropdown/collapse state is React-owned, the rule this ADR's own Decision and `frontend/CLAUDE.md`'s Tabler section both already state), so without the attribute a horizontal-navbar `.dropdown-menu` falls back to its hypothetical static-flow position and visually overlaps its own toggle. This is a genuine Tabler-vs-"we don't vendor the JS" incompatibility this ADR's own text didn't anticipate, not a defect introduced by the header restyle itself — every existing e2e test closed the affected dropdowns via `Escape`/click-outside/selecting an item, never by re-clicking the toggle, which is exactly why it went uncaught until now.

**Fix:** `data-bs-popper=""` set statically on the two header `.dropdown-menu` elements (org-switcher, color-mode) — a pure CSS hook satisfying the attribute-presence selector, not a request for real Popper behavior; nothing reads its value or treats its presence as a signal to auto-initialize JS (confirmed: no `data-bs-toggle="dropdown"` is set on either trigger, which is what Bootstrap's own auto-init actually scans for). The sidebar's entity-group dropdowns are unaffected — confirmed live (CDP-verified) that Tabler's vertical-navbar dropdown-menus resolve to `position: static` instead, sidestepping this gating rule entirely, consistent with this ADR's own "inline, not flyout" finding above.

A new e2e regression test (`shell6-org-switcher.spec.ts`) asserts the toggle-click-to-close path directly, not just the previously-covered `Escape`/click-outside/select-an-item paths.

## Alternatives considered

- **Reskin sidebar+header with Tabler CSS loaded alongside AdminLTE, scoped to just those two components.** Rejected — Tabler ships no scoped/namespaced build, and both frameworks define the same unscoped global selectors (`.card`, `.btn`, `.dropdown-menu`, ...); "scoping" would require hand-written override CSS fighting the cascade, against this repo's own "use the library's own classes verbatim, no hand-written CSS" norm (ADR-0042).
- **Translate the Tabler layout shape into AdminLTE's own existing classes (no new CSS, no ADR).** Rejected — the CTO's explicit ask was to adopt Tabler's own markup, confirmed via `AskUserQuestion`, not merely to restructure the AdminLTE sidebar to resemble Tabler's layout.
- **Full big-bang migration of the entire app in one branch, mirroring ADR-0042's own CoreUI→AdminLTE cutover exactly.** Rejected for this pass — out of the CTO's stated scope ("sidemenu and header"); a full-app swap is left as explicit future work, tracked by ADR-0042's partial-supersession status rather than attempted here.
- **Keep AdminLTE winning the cascade, hand-write Tabler-equivalent override CSS for just the 4 shell components.** Rejected via the second `AskUserQuestion` round — more hand-written CSS (against the "no custom CSS" norm) for a narrower, still-temporary win; the CTO chose to accept the repo-wide visual shift instead, consistent with treating this as a real (if incremental) design-system direction change rather than a contained reskin.
- **Keep the `sidebar-mini` icon-rail behavior, reimplementing it against Tabler's `navbar-folded-hover`.** Deferred, not rejected — real, scoped work (a `data-bs-toggle="sidebar-folded"` pin button, `localStorage` persistence, `tabler:sidebar-folded` event wiring) that the CTO's own "sidemenu and header" instruction didn't ask for this pass; tracked as the "Known open item" above rather than silently dropped or silently built.

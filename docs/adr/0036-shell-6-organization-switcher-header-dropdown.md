# ADR-0036: SHELL-6 — organization switcher header dropdown + `GET /auth/me/orgs` org-membership endpoint

**Date:** 2026-09-07
**Status:** Accepted
**Deciders:** xuanbinh91@gmail.com (CTO)
**Related:** [ADR-0007](0007-real-multi-tenancy.md) (real multi-tenancy — origin of the org-picker UX requirement), [ADR-0018](0018-admin-shell-sidebar-layout.md)/[ADR-0020](0020-admin-shell-full-template-parity.md) (`AppHeader`/`AppShell`, and the existing dark/light-mode header-dropdown precedent this reuses), [ADR-0035](0035-dash-1-root-redirect-and-dashboard-placeholder.md) (documents the AUTH-2 `orgContext`/`orgs`-not-restored-on-reload gap and explicitly deferred fixing it — "revisit if/when a future org-scoped feature needs it," which this ADR is), [SHELL-6 user story](../user-stories/2026-09-04-admin-shell-sidebar-stories.md), [SHELL-6 UI Design Document](../ui-design/2026-09-07-shell-6-org-switcher-ui-design.md)

## Context

Today there is no way to switch which organization you're working in without leaving the app shell entirely: the only routes are `/orgs/pick` (shown once, right after login, only while `AuthContext.orgs` is populated) and hand-editing the `/orgs/:orgId` URL. `AuthContext`'s `orgs`/`orgContext` fields are set only by `login()`/`signup()`/`acceptInvite()` responses and are never refreshed afterward (`AuthContext.tsx`'s own docstring) — so even the existing `/orgs/pick` screen goes blank on a page reload, a gap ADR-0035 fixed around for `/` specifically by never depending on `orgContext` there, while explicitly flagging that the underlying gap would resurface for "the first story that gives [org-scoped content] real content." A persistent header org-switcher is exactly that story: it must work on every authenticated page, including immediately after a reload, so it cannot rely on the login-time-only `orgs` array either.

`org_id` is never carried in the JWT (`create_access_token` only encodes `sub`); every gated route resolves it from the URL path param (`app/core/rbac.py`'s `require_permission`). Practically, this means "switching org" needs no token reissue — it's a client-side navigation to a different `/orgs/{orgId}` tree, permission-gated per-route exactly as today, by that org's own `RoleAssignment`s.

## Decision

- **New backend route `GET /auth/me/orgs`** ([API Document](../api/2026-09-03-api-design.md) §2) — authenticated (human `User` bearer only; the header is human-only chrome, `AIAgent` actors never carry an `OrgMembership` row per `backend/CLAUDE.md`'s "OrgMembership existence check" note), no `org_id` path param (identity-scoped, not this org's own resource — matches `organizations.py`'s own existing comment that "list isn't registered either... 'orgs I belong to' is an identity-based filter, not this factory's exact-match-scope shape"). Response: `{orgs: OrgSummary[]}`, reusing the exact `OrgSummary {id, name, slug}` schema `LoginResponse` already returns — **no new schema**. Resolved from `OrgMembership` rows with `status = active` only, same rule `POST /auth/login`/`POST /auth/refresh` already apply (API Document §2 line 66) — `suspended`/`invited` memberships never appear.
- **Frontend: `AppHeader` gains a new `CDropdown`** (icon: `cilBuilding`, tooltip "Switch organization"), placed in the header alongside the existing color-mode-toggle dropdown — the same `CDropdown`/`CDropdownToggle`/`CDropdownMenu` shape ADR-0020 already established as this app's header-dropdown pattern (`AppHeader.tsx`'s color-mode toggle is the direct precedent, cited there for the same reason).
- **Lazy-fetch**, not boot-fetch: the dropdown calls `GET /auth/me/orgs` only when it's opened, not on `AuthContext` init or on every route change. Simplest correctness posture given there's no cache-invalidation event yet for "an org was created/left elsewhere" — every open is a fresh read. `AuthContext`'s existing `orgs`/`orgContext` fields are untouched by this ADR; they remain login-time-only, still driving `Login.tsx`'s own separate post-login redirect.
- **Dropdown always renders**, even for a single-org account — no conditional hide/disable at exactly 1 org, avoiding a layout shift and treating "how many orgs" as UI-irrelevant.
- **Selecting an org always navigates to that org's root, `/orgs/{id}`** — never attempts to preserve the current nested sub-route (e.g. staying on a `/members` or `/admin/:entity` equivalent) across the switch. A resource ID nested under the current org (a project ID, a test plan ID, ...) has no meaning in the target org, so re-resolving from the org root is the only safe target.
- **No "create new organization" action inside the dropdown.** It is switch-only; org creation remains solely on `/orgs/pick`'s existing modal, reached via `/orgs/pick` directly (not linked from the dropdown itself in this pass — see Alternatives).
- **Current org is visually indicated** in the list when the active route is under `/orgs/:orgId` (matched via `useParams().orgId`) — no new state, purely a render-time comparison against the fetched list.
- **UI Design Document lives as its own file**, `docs/ui-design/2026-09-07-shell-6-org-switcher-ui-design.md`, not folded into this ADR's own prose — matching the convention every story since PLAN-1 has used (7 of 7), even though the pre-PLAN-1 admin-shell work (SHELL-1 through SHELL-5) predates that convention and never got one retroactively. Explicit choice, not a default inherited from the older sibling stories in the same feature area.

## Consequences

**Positive:** Zero schema change — reuses `OrgSummary` verbatim. Zero token/session change — `org_id` was already URL-resolved, not JWT-carried, so switching is pure client-side navigation. Reuses an already-proven header-dropdown UX pattern (ADR-0020) rather than inventing a new one. Closes the practical "no way to switch org mid-session" gap without touching the boot-time silent-refresh flow at all.

**Negative / accepted trade-offs:**

- **Lazy-fetch re-queries `GET /auth/me/orgs` on every dropdown open**, not just once per session — acceptable at scaffold scale (a handful of orgs per user, an infrequently-opened dropdown), but a future story adding real caching (React Query with a short `staleTime`, or promoting this into `AuthContext` with an explicit invalidation event) should treat this as the obvious next step rather than a surprise.
- **The full AUTH-2 gap is still not closed.** `AuthContext.orgs`/`orgContext` remain populated only at login time; a page reload still leaves them empty, and any *other* future feature that assumed a live, boot-populated org list in context (rather than fetching its own copy the way this dropdown does) would still hit the original gap. This ADR closes it only for the one surface that needed it.
- **Permission-derived UI elsewhere (sidebar nav, admin surfaces) is not explicitly re-synced on switch** — relies on each screen's own existing server-side permission check (every route already re-gates per `org_id`) to self-correct on the next render/fetch after navigation. No client-side permission cache exists today to go stale in the first place, so this is expected to be a non-issue, but it's called out as an open verification point for implementation (an org switch into a role with fewer permissions must not transiently show a now-forbidden action before its next successful fetch fails).

## Alternatives considered

- **Fetch orgs on `AuthContext` boot/refresh instead of lazily.** Considered as the plan's original default; explicit CTO direction picked lazy-fetch instead — avoids an extra network call on every page load for a dropdown that may never be opened, and sidesteps the question of when a boot-cached copy would need invalidating.
- **Extend `POST /auth/refresh`'s response to include `orgs`**, closing the full AUTH-2 gap directly. Rejected for this pass: `POST /auth/refresh`'s contract is deliberately minimal (`{access_token}` only, per ADR-0013) and changing it is a broader decision than this one header control needs; a dedicated identity-scoped `GET /auth/me/orgs` is more reusable (any future org-scoped feature can call it independently of the refresh cycle) and keeps ADR-0013's existing contract untouched.
- **Preserve the current nested sub-route across a switch** (e.g. switching org while on a members-equivalent page lands on that same page in the new org). Rejected — nested resource IDs (project, test plan, ...) don't transpose across orgs; only the org-root path is guaranteed valid in the target org.
- **Add a "New Organization" shortcut inside the dropdown**, duplicating `OrgPicker`'s existing create modal. Rejected — keeps the dropdown to one job (switching), avoids duplicating modal logic; `/orgs/pick` remains the single place org creation happens.
- **Fold this ADR's UI description into itself rather than a separate UI Design Document**, matching the pre-PLAN-1 admin-shell precedent (ADR-0018/ADR-0020 both did this). Rejected — every story since PLAN-1 uses a separate `docs/ui-design/*.md` file; matching current convention over a superseded older one.

# ADR-0043: DS-3 shared `InfoBox` component (AdminLTE Info Box markup), retires `WidgetStatsTile` + `StatTile`

**Date:** 2026-09-08
**Status:** Accepted
**Deciders:** xuanbinh91@gmail.com (CTO)
**Related:** [ADR-0042](0042-adminlte-design-system.md) (AdminLTE v4 design system — this ADR is an instance of its "raw HTML against the library's own documented markup" rule, not a new architecture decision of its own), [ADR-0023](0023-frontend-shared-component-location.md) (frontend shared-component location — `components/shared/`, stateless-composition axis, unchanged by this ADR), [ADR-0041](0041-ds-2-table-container-shared-pagination.md) (DS-2, the prior instance of the same "independently-evidenced duplication → one shared component" pattern, applied to tables), [DS-3 user story](../user-stories/2026-09-04-design-system-component-stories.md#story-ds-3-reusable-infobox-metric-tile), [DS-3 UI Design Document](../ui-design/2026-09-08-ds-3-infobox-widget-consolidation-ui-design.md)

## Context

A direct product ask (CTO): the two count widgets on `/orgs/:orgId` (Project count, active Org Member count) should use AdminLTE v4's own documented **Info Box** widget (https://adminlte.io/themes/v4/widgets/info-box.html) instead of the CoreUI-free-template-derived tile they use today. Scope was widened to repo-wide during planning, on the CTO's own instruction, once an audit (2026-09-08) found this is not an isolated case — the same "hand-rolled stat tile, independently reinvented" duplication DS-2 evidenced for tables exists again, one level down, for small metric tiles:

| Component | Location | Usages | Markup shape |
|---|---|---|---|
| `WidgetStatsTile` (`components/shared/widget-stats-tile/`) | `OrgHome.tsx` only | 2 (Project count, active Org Member count) | `div.card.overflow-hidden` > `div.card-body.p-0.d-flex.align-items-center` > optional icon block (`bg-{color} text-{contrast} p-4 me-3`) + value/title stack (`fs-6 fw-semibold`/`text-body-secondary text-uppercase fw-semibold small`) |
| `StatTile` (local, unexported) | `TestCycleDetail.tsx:278` only | 4 (execution-dashboard Pass/Fail/Blocked/Skipped) | `div.col-6.col-md-3.mb-3` (caller-owned column, unlike `WidgetStatsTile`) > `div.card.h-100.text-center` > `div.card-body.py-3` > label (`text-body-secondary small text-uppercase`) + value (`fs-3 fw-semibold text-{color}`, `null` → `"—"`) |

Neither shape is AdminLTE's own Info Box markup (`.info-box`/`.info-box-icon`/`.info-box-content`/`.info-box-text`/`.info-box-number`, confirmed present in `admin-lte/dist/css/adminlte.css:14857`) — both are hand-rolled Bootstrap-card compositions that predate [ADR-0042](0042-adminlte-design-system.md)'s design-system swap (`WidgetStatsTile`'s own file header cites the CoreUI free-template demo as its origin) and were carried forward by ADR-0042's markup-only reclass rather than replaced. Grepped for any other "big number in a small card" pattern repo-wide (`fs-[1-6] fw-(bold|semibold)` + `card`/`card-body` combinations across `frontend/src`); none found beyond these two.

## Decision

- **New `frontend/src/components/shared/info-box/InfoBox.tsx`** — presentational only (stateless, `components/shared/` axis per ADR-0023, same tier `WidgetStatsTile` and `FormField` already occupy; not `container/`, since this component owns no state/actions of its own, unlike DS-2's `Table`).
- **Markup**, copied verbatim from AdminLTE v4's own shipped CSS contract (`.info-box` > optional `.info-box-icon` + `.info-box-content` > `.info-box-text` + `.info-box-number`), to be confirmed against a live render (RTL DOM dump or an isolated stack) for the exact contextual-color utility class on `.info-box-icon` before implementation — `frontend/CLAUDE.md`'s own "dump the real DOM, don't invent a class name" rule, since AdminLTE's SCSS source bakes in no color of its own (verified: `_info-box.scss` has zero `bg-`/`text-` references).
- **Props** (superset of both retired components' contracts): `color` (reuses the existing `CWidgetStatsColor` enum unchanged — every color both retired components use, `primary`/`info`/`success`/`danger`/`warning`/`secondary`, is already a member), `text` (label), `number` (`ReactNode` — carries `WidgetStatsTile`'s existing Loading…/Unable to load/count tri-state *and* `StatTile`'s `null`→`"—"` sentinel; the component itself stays agnostic to which convention a given caller uses, same posture `WidgetStatsTile` already had for its `value` prop), `icon` (optional FA class string — omitted renders no icon block, present renders one; **the grid-column wrapper stays caller-owned**, matching `WidgetStatsTile`'s existing contract, not `StatTile`'s self-wrapping one — `OrgHome.tsx` already supplies its own `col-sm-6` wrapper per widget, confirmed at `OrgHome.tsx:497-504`), `testId`.
- **Two call sites migrate, six data flows unchanged**: `OrgHome.tsx`'s `ProjectCountWidget`/`ActiveMemberCountWidget` (their own `useQuery`/`widgetValue` loading-error-count logic is untouched — only the rendered component changes) and `TestCycleDetail.tsx`'s 4 dashboard tiles (`counts.pass`/`.fail`/`.blocked`/`.skipped`, `null`-safe, untouched). Every existing `data-testid` (`widget-project-count`, `widget-active-member-count`, `dashboard-tile-{pass,fail,blocked,skipped}[-count]`) carries over verbatim — no test-id renumbering.
- **`ActiveMemberCountWidget` gains an icon it didn't have before** (`fa-solid fa-users`, matching `ProjectCountWidget`'s existing `fa-solid fa-folder`) — Info Box's own canonical demo shape always shows the icon block; there is no documented "B-variant" the way the old CoreUI-demo tile had one. `TestCycleDetail`'s 4 tiles stay icon-less (no natural icon for a bare count, and Info Box's icon block is optional in this component's own contract even though the demo doesn't showcase omitting it).
- **`WidgetStatsTile` and `StatTile` are both deleted** once their call sites migrate — `components/shared/widget-stats-tile/` (component + barrel + its own Vitest file) removed outright, `TestCycleDetail.tsx`'s local `StatTile` function removed. Neither has any caller left afterward; no dead code retained "for future reuse," consistent with ADR-0042's own zero-leftover posture.

## Consequences

**Positive:** One shared metric-tile implementation instead of two independently-hand-rolled ones, using AdminLTE's own documented widget verbatim rather than a component carried over from the pre-AdminLTE CoreUI demo. Closes the same class of duplication DS-2 (ADR-0041) closed for tables, one component-class down. `TestCycleDetail`'s dashboard tiles and `OrgHome`'s count widgets now share one visual language instead of two divergent card shapes.

**Negative / Trade-offs:** `ActiveMemberCountWidget`'s new icon is a real, visible change (a widget that rendered no icon block for its whole history now shows one) — accepted, since Info Box's canonical shape doesn't offer an icon-omitted variant in the reference design, and a bare Info Box with an empty `.info-box-icon` slot would look like a rendering bug rather than an intentional B-variant the way the old component's omitted-icon path did. `InfoBox`'s `number` prop carries two different sentinel conventions (`WidgetStatsTile`'s loading/error strings, `StatTile`'s `null`→`"—"`) with no shared contract between them — same posture `WidgetStatsTile` already had (caller-owned formatting), not a new looseness this ADR introduces, but worth naming since a future third caller could invent a third convention with nothing in the component's types to prevent it.

## Alternatives considered

- **Keep `WidgetStatsTile` and `StatTile` as two separate components, only reskin `WidgetStatsTile`'s markup** — rejected per explicit CTO direction (repo-wide scope): leaves the exact duplication this ADR exists to close, evidenced identically to what justified DS-2's table consolidation.
- **A more general `MetricTile`/`Widget` abstraction covering trend charts, progress bars, or other AdminLTE small-box variants** — rejected: no third usage shape exists in this codebase today: same no-fabrication discipline DS-1's own business case established (`docs/user-stories/2026-09-04-design-system-component-stories.md`'s scope note) — build to evidenced duplication, not to a hypothetical future one.
- **Give `TestCycleDetail`'s 4 tiles an icon too, for visual consistency with `OrgHome`'s widgets** — rejected: no natural icon exists for a bare pass/fail/blocked/skipped count (unlike "Projects"/"folder" or "Members"/"users"), and inventing one risks a misleading glyph; `InfoBox`'s icon stays optional specifically so this call site can omit it.
